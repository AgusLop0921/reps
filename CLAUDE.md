# CLAUDE.md

Operating context for this project. Read it fully before touching code.

## What this is

**Reps** is a mobile-first web app for learning technical subjects through short daily
lessons. It exists to take the place of aimless scrolling: same
reflex, same two-second cost to open, something to show for it afterwards.

Content is imported from approved third-party sources or explicitly identified as Reps
editorial content, then normalized into a shared schema.

The value here is **not** displaying questions — that already exists (e.g. reactjs.wiki).
It is structure and progression: an ordered path, one lesson at a time, with earlier
material resurfacing before you forget it.

## Shape of the product

- A **linear path** of lessons, grouped into level sections (basic → expert).
- You start at lesson 1 and move forward. Finishing a lesson unlocks the next one.
- Each level section can be entered directly: someone experienced can jump straight to
  Advanced without grinding through Basic. Within a section, order is enforced.
- A lesson is a handful of questions plus a few review cards from earlier lessons.
- **Not a feed.** No infinite scroll, no algorithmic timeline, no endless content. A
  lesson has an end, and reaching it is the point.

## Language policy (ADR-0008)

- **Repository is English**: code, identifiers, comments, docs, ADRs, commits, PRs, tests.
- **Product is Spanish**: every user-facing string, because the imported content is Spanish.
- Never translate imported content; never write UI strings in English.
- UI chrome lives in `src/ui/copy.ts`; imported or reviewed editorial learning material lives
  in canonical content data. Spanish elsewhere is a defect; English UI copy is a defect.

## Non-goals (v1)

Do not implement these even if they look like an obvious improvement. If you think one
should change, propose an ADR — do not act on it.

- No feed, no infinite scroll, no recommendation algorithm.
- No backend for content or app logic, and no server-side database of questions — the
  corpus stays static and client-side. The original "no accounts, no cross-device sync"
  non-goal was superseded under ADR-0020/0021/0022: optional Supabase sync (magic-link or
  Google accounts, progress only) is off unless configured, and IndexedDB stays the source
  of truth.
- No global state library. React state and context are enough.
- No AI calls in the app at runtime. Interview simulation is v2 and lands under ADR-0013;
  build-time check generation (maintainer's key, output committed) is ADR-0017.
- No i18n framework.
- No punishing streaks, no push notifications, no guilt mechanics (ADR-0010).
- No unattributed hand-written source content. Imported content comes from approved sources;
  explicitly reviewed editorial seeds use a `manual` source. Multiple-choice checks remain
  separate from imported answers (ADR-0017, ADR-0023).

## Commands

Available today:

```bash
pnpm dev            # Vite dev server
pnpm build          # tsc --noEmit + vite production build
pnpm test           # vitest
pnpm lint           # eslint
pnpm typecheck      # tsc --noEmit
pnpm content:import # regenerate src/content/data/* from sources
pnpm verify         # typecheck + lint + test — run before claiming you are done
```

## Layout and dependency rules

```
src/
  content/     # sources, tracks, schema, types, seed and generated data; no core/ or ui/
    data/      # GENERATED by pnpm content:import. Never edit by hand.
    schema.ts  # source of truth for the data model (Zod)
    order.ts   # hand-curated curriculum overrides (ADR-0011)
  core/        # pure logic. No React, no DOM, no clock — `now` is a parameter.
    curriculum.ts  # path position, unlocking, next lesson
    scheduler.ts   # spaced repetition for review cards
  storage/     # persistence (Dexie/IndexedDB). Only layer touching browser storage.
  ui/          # React components. No business logic.
    copy.ts    # every Spanish user-facing string
scripts/import/
  sources/       # one adapter per content source
  analysis/      # provider-neutral grounded analysis and build-time provider adapters
docs/adr/      # architecture decisions
```

Non-negotiable: **`core/` is pure and tested**. If a function needs `Date.now()`,
`localStorage` or `fetch`, it does not belong there.

## Conventions

- Strict TypeScript. `any` is banned; use `unknown` and validate.
- Zod validates at the boundaries: imported content and data read from IndexedDB.
- Vitest covers all of `core/` and every adapter. UI is not tested in v1.
- Domain vocabulary: `source`, `track`, `lesson`, `section`, `question`, `review`, `box`,
  `path`. A source is provenance; a track is a learning experience. Do not conflate them or
  introduce Module/Exercise synonyms for existing Section/Question+Check concepts (ADR-0023).

## Git workflow (ADR-0009)

- `main` is always releasable. Never commit directly to it.
- One branch per concern: `feat/…`, `fix/…`, `docs/…`, `chore/…`, `refactor/…`.
- **Atomic commits**: one commit does one thing and leaves the tree green. If the message
  needs "and", split it. Never mix a refactor with a behavior change.
- Conventional Commits, English, imperative: `feat(core): add lesson unlocking`.
- Generated files (`src/content/data/`) always get their own commit.
- One PR per branch, squash on merge. Open it with `/pr`.
- **Never push to `main` and never merge your own PR.**

## How to work

1. **Plan before code.** Anything touching more than one file: write the plan, wait for
   approval.
2. **One structural decision = one ADR.** Use `/adr`.
3. **New dependencies: always ask.**
4. **Never invent imported content.** If an adapter cannot parse something, fail loudly. Do
   not fill a missing source answer from your own knowledge — imported content stays
   traceable. Generated MCQ checks (ADR-0017) and explicitly reviewed editorial material are
   ours, stay separate from imported answers, and use Reps provenance.
5. **Definition of done:** `pnpm verify` green, ADR written if needed, PR open.

## Third-party content

Every source has its own license and mandatory attribution (ADR-0007, `docs/sources.md`).
Verify the license before writing an adapter, store its text in `licenses/<source-id>.txt`,
tag every question with `sourceId`, never edit imported answers. Report upstream errors
upstream.

Future source ingestion must pass an explicit source-policy/licensing boundary and publish
only validated canonical Reps content. Runtime UI must not fetch arbitrary sources or call an
AI generator; generated candidates require grounding, validation, and review (ADR-0023).
